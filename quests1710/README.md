# Sigmarix Quests — Forge 1.7.10 prototype

Самостоятельная реализация базовых функций квестов для Minecraft 1.7.10,
Forge 10.13.4.1614 и Java 8. Версия 0.1.0 — **не полный порт FTB Quests**.
Код, графика и название мода FTB не включены. Нет зависимости от FTBLib.

## Установка и работа

Установите `build/libs/quests1710-0.1.0.jar` в `mods` сервера или одиночного
клиента Forge. В многопользовательской игре клиенту этот мод не требуется:
весь интерфейс пока работает через чат. При первом запуске создаётся
`config/sigmarixquests/quests.json` с четырьмя примерами.

- `/quests` или `/quests list` — задания и состояния.
- `/quests show <id>` — описание, требования, награды.
- `/quests check <id>` — проверка всех требований и завершение задания.
- `/quests claim <id>` — однократное получение награды.
- `/quests reload` — перезагрузка JSON, только для оператора уровня 2 или консоли.
  Ошибка оставляет предыдущую книгу активной. При ошибке начальной загрузки сервер
  прекращает запуск мода, чтобы не потерять задания незаметно.

Идентификаторы квестов должны быть уникальны; зависимости ссылаются на завершённые
квесты, награду за них получать заранее не требуется. Круговые и неизвестные
зависимости, неизвестные типы заданий, предметы и существа отвергаются.

Типы заданий:

| `type` | Поля | Поведение |
| --- | --- | --- |
| `check` | — | Подтверждение командой check |
| `item` | `target`, `count`, `meta` | Проверка основного инвентаря; предметы не расходуются |
| `kill` | `target`, `count` | Убийства игроком, включая стрелы; считаются после открытия квеста |
| `dimension` | `dimension` | Игрок должен быть в этом измерении в момент check |

`target` предмета — registry ID (`minecraft:cobblestone`), существа — имя
EntityList (`Zombie`). `meta` по умолчанию 0, `count` — 1. Совпадающие задания
на предметы внутри одного квеста суммируются. NBT предметов не проверяется.
Все требования должны выполняться одновременно при `/quests check`.
Награды задаются как `{"item":"minecraft:bread","count":4,"meta":0}`.
Остаток награды, не поместившийся в инвентарь, выпадает рядом с игроком.

Прогресс хранится в `data/sigmarixquests.dat` основного мира по UUID игрока.
Завершение квеста и получение награды — отдельные состояния. Счётчики убийств
сохраняются вместе с миром. Обычное повторное получение награды запрещено.
Как и инвентарь Minecraft, изменения зависят от сохранения мира: защита от
отката/дублирования при аварии процесса между сохранениями не реализована.

## Сборка и проверки

В подготовленном окружении:

```bash
source /workspace/minecraft-1.7.10/env.sh
cd /workspace/Sigmarix/quests1710
mc-gradle build
```

Сборка использует RetroFuturaGradle 2.0.6, Java 8 для мода и выполняет
reobfuscation. `-dev.jar` не предназначен для установки в обычную игру.
JUnit-тест, включённый в `check`, проверяет зависимости, циклы,
ошибочные определения, суммирование предметов без переполнения, NBT roundtrip,
разделение игроков по UUID, сохранение получения наград и лимит счётчика убийств.

Ручная проверка в игре: выполнить welcome, дважды запросить его награду,
собрать 16 булыжника для stone, убить трёх зомби для hunter, выполнить nether
в измерении -1, перезапустить мир и проверить сохранение состояний.
Графический клиент и Crucible пока не проверены.

## Что осталось для полного порта

Графическая книга и редактор, главы и размещение узлов, команды/опыт/жидкости
в наградах и заданиях, команды игроков, синхронизация GUI, импорт формата FTB,
интеграции с другими модами. JSON этой реализации несовместим с форматом FTB.
Изменение порядка kill-заданий меняет привязку счётчиков; после начала игры
сохраняйте ID и порядок заданий либо планируйте миграцию/сброс прогресса.

Для исследования использована публичная ветка `1.12` FTBTeam/FTB-Quests,
commit `85b7652bd69f3bc4c03ba9ba24909ddea0605a53`:
https://github.com/FTBTeam/FTB-Quests/tree/1.12
В ней 295 Java-файлов и зависимости от FTBLib/ItemFilters для 1.12.2.
Файл лицензии в этом checkout отсутствует. До копирования/распространения
кода оригинального мода нужно установить применимые условия.
